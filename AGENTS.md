# Royalty Buyer project rules

- This project is a faithful, multi-page relabel of `cesiumastro.com`. Preserve the donor DOM, cinematic full-height media bands, three-column editorial band, applications cadence, typography, navigation behavior, newsroom grid, product-detail hierarchy, and page-family distinctions.
- The homepage hero must contain one visible, nonempty, SEO-driven H1 naming the core service and market. A blank hero image is a release-blocking defect.
- This is a business website, never a personal blog. Singular first-person editorial language (`I`, `me`, `my`, `myself`) is forbidden in authored and rendered copy. Owner FAQ questions use direct second person; company explanations use Royalty Buyer's institutional voice.
- The writing belongs only to `royaltybuyerusa.com`: an empathetic but exact royalty desk shaped by a fourth-generation ranch family's own mineral sale. It explains how land, family history, documents, cash flow, and closing terms fit together. Never copy this voice into another domain, a shared pack, or a reusable template.
- Use only the mapped local image inventory in `images/` and its staged `public/ours/` copy. No donor photos, remote content images, placeholders, blank media frames, or unrelated stock images.
- Do not render miniature decorative pictures anywhere. Footer media must be exactly zero: no `img`, `picture`, `svg`, `video`, `canvas`, `iframe`, or `source`.
- The street address may exist only in metadata and the single Google Maps embed on the contact page. It must never appear as visible text.
- Keep all seven taxonomies visible and internally linked through the homepage, header, footer, index pages, and detail pages without replacing CesiumAstro's editorial cadence with repetitive generic boxes.
- A release requires capture parity, content normalization, structural verification, the project compliance scan, full-resolution donor-versus-built review, desktop and mobile browser QA, clean nested-repository git proof, and live Vercel route and form verification.
